8. Attack Scenarios & Mitigation

SSL-Stripping / Downgrade Attack HIGH

Attack Scenario:

An attacker on the same network (e.g. public WiFi) intercepts the first HTTP request and redirects the user to an unencrypted HTTP version of the site. Tools like sslstrip automate this attack. All entered data (login, forms) is transmitted in plaintext.

Impact:

Credential interception, session hijacking, man-in-the-middle attack

Mitigation:

HSTS header enforces HTTPS in the browser. After the first visit, the browser refuses HTTP connections.
Cross-Site Scripting (XSS) HIGH

Attack Scenario:

An attacker injects malicious JavaScript code into the website, e.g. via a comment field, URL parameters, or compromised third-party scripts. Without CSP, the browser executes any embedded code.

Impact:

Session cookie theft, redirection to phishing sites, keylogging, data exfiltration

Mitigation:

CSP defines allowed sources for scripts, styles, and media. Unauthorized code is blocked by the browser.
Clickjacking MEDIUM

Attack Scenario:

The website is invisibly embedded in an iframe on an attacker's page. The user believes they are clicking harmless buttons, but actually triggers functions on the embedded original site (e.g. transfers, setting changes).

Impact:

Unintended actions on behalf of the user, account manipulation

Mitigation:

X-Frame-Options: SAMEORIGIN prevents embedding in third-party sites.
MIME-Type Confusion MEDIUM

Attack Scenario:

An attacker uploads a file disguised as a harmless image that actually contains JavaScript code. Without the nosniff header, the browser may 'guess' the MIME type and interpret the file as executable code.

Impact:

Execution of malicious code in the browser context

Mitigation:

X-Content-Type-Options: nosniff forces the browser to respect the declared MIME type.
Information Leak via Referrer Header LOW

Attack Scenario:

When a user clicks an external link from the site, the browser sends the full URL (including search terms, session IDs, tokens in query parameters) as Referrer to the target site.

Impact:

Leak of sensitive URL parameters, session tokens, internal paths

Mitigation:

Referrer-Policy: strict-origin-when-cross-origin sends only the domain, not the full path.
